# Deploying VALENIZED to Hostinger

This site is **static + 1 PHP file**. Hostinger's shared web hosting (any
plan with PHP enabled — even the cheapest) supports it natively.

---

## Step 1 · Get everything in `public_html/`

In Hostinger's File Manager (or via FTP), navigate to the root of your
domain — usually:

```
/domains/valenized.com/public_html/
```

Upload the **entire contents** of `site/` so that the structure looks like:

```
public_html/
├── index.html
├── about.html
├── works.html
├── contact.html
├── terms.html
├── contact.php
├── styles/
├── scripts/
├── assets/
└── logs/             ← create this empty folder manually
```

> ⚠ The `logs/` directory **must exist with 0755 permissions** before
> `contact.php` can write to it. If `contact.php` ever returns 500, this
> is the first thing to check. Create the folder via File Manager →
> New Folder → name it `logs` → right-click → Permissions → 0755.

## Step 2 · Configure `contact.php`

Open `contact.php` and edit the two constants at the top:

```php
const TO_EMAIL   = 'inquire@valenized.com';   // destination mailbox
const FROM_EMAIL = 'no-reply@valenized.com';  // sender — MUST be on your domain
```

**Why the FROM address matters**: Hostinger (and most shared hosts) require
the `From:` header to be on a mailbox that's actually hosted on their
servers, or `mail()` quietly drops the message. You need to log into
Hostinger's **Emails → Manage** and create `no-reply@valenized.com` first.

## Step 3 · Create the mailboxes

In Hostinger panel:

1. **Emails** → select `valenized.com` (or whatever your free domain is)
2. **Manage** → **Create a new email account**
3. Create two accounts:
   - `inquire@valenized.com` (this is where leads land)
   - `no-reply@valenized.com` (this is the `From:` sender)
4. Both can use the same mailbox password if you like
5. Wait ~5 minutes for DNS propagation

You can now **read inbound leads** at `inquire@valenized.com` either
through:

- **Hostinger webmail** (roundcube) → `mail.hostinger.com` / domain-specific URL
- Any external client (Gmail, Apple Mail) via IMAP — Hostinger shows the
  IMAP / SMTP settings in the panel

## Step 4 · DNS sanity check (Hostinger handles this for the domain if
the free domain is in their account)

Verify these records exist (Hostinger auto-adds them, but worth checking):

```
Type   Host   Value
MX     @      mx1.hostinger.com   (priority 10)
MX     @      mx2.hostinger.com   (priority 20)
TXT    @      v=spf1 include:_spf.hostinger.com ~all
```

Optional but recommended (improves deliverability):

```
CNAME  mail._domainkey   →  <auto-generated DKIM host>
TXT     _dmarc            →  "v=DMARC1; p=none; rua=mailto:inquire@valenized.com"
```

## Step 5 · Single-page-functionality smoke test

Before showing the client, do these 5 tests:

| # | Action | Expected |
|---|---|---|
| 1 | Open `https://valenized.com/` | Loads the home page with the loader, then chrome-orb hero |
| 2 | Click through all nav links (Index / About / Works / Contact / Terms) | Each loads with the split-pane transition |
| 3 | On Works, click each filter chip | Tiles fade in/out per category |
| 4 | Resize from desktop → phone (DevTools) | Hamburger shows under 900 px, tiles stack under 720 px |
| 5 | Submit the contact form | Success modal pops; check `inquire@valenized.com` inbox; check `public_html/logs/submissions.log` exists with a new line |

## Step 6 · Common pitfalls

| Symptom | Fix |
|---|---|
| Loader never dismisses | JS error — open DevTools console, fix before debugging |
| Form "submits successfully" but no email arrives | `From:` sender isn't a real mailbox on the domain. Create `no-reply@valenized.com` in Hostinger Emails panel. |
| `logs/submissions.log` permission denied | Folder missing or wrong perms — set `logs/` to 0755, `submissions.log` will be auto-created by the script |
| Chrome-orb hero not animating | Client has `prefers-reduced-motion: reduce` set — this is expected behavior |
| Tile hover distortion doesn't work | GPU disabled in browser, or `prefers-reduced-motion` is on |
| Mobile menu link closes immediately | None — should not happen with current build |

## Step 7 · After the client sends real copy

Two ways to swap the lorem for real text:

1. **Manual** — open each `.html` in Hostinger File Manager, paste real copy.
   Look for the strings flagged in `README.md` § "What's intentionally placeholder".

2. **From local** — edit files locally with the real copy, then re-upload.
   Faster for large batches; safer because you have local backups.

## Booking the free domain one-year expiry

Your free domain lasts 12 months from issue. To keep it after expiry:

- Set a calendar reminder 30 days before expiry
- In the Hostinger panel → **Domains** → enable auto-renew OR renew the
  free voucher for a second year (if still on a qualifying plan)
- If the domain drops, **back up all mail** on `inquire@valenized.com`
  *before* expiry — Hostinger wipes MX records when the domain is gone
